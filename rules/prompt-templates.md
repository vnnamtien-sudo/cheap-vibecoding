# 提示词模板

【】里的数按你的项目和电脑改。

## 模板 A：开新对话时的开工卡

```markdown
【开工卡】
型号：【Opus】；档位：【high / xhigh】。

1. 少读：读文件先搜行号、每次 ≤ 60 行；大块旧代码派一次性子代理读、只交回 ≤ 150 字；查数、测试明细写临时文件，屏幕只打 ≤ 15 行结论。
2. 本棒目标：做完一个四样齐（读、写、接口或页面、测试）、能独立验的小功能。上下文到约【25 万】还没交出能验的东西，就把精确数字、改动文件路径、下一步入口写进交接单，结束对话。
3. 测试一律走排队器（node <cheap-vibecoding 目录>/tools/test-queue.cjs run --label <label> -- …），开发期只跑点到的测试。
4. 只读这三样就开工：交接单【路径】、方案【路径】、要改的文件【清单】。不读旧对话，不逐行翻旧代码。

读完交接单，用一句话报出本棒目标，立即动手。
```

## 模板 B：交接单

```markdown
# 交接：【功能名】 第【N】棒

- 做完了：【一句话】；改动文件：【路径清单】
- 精确数字：【测试 x/y 通过；对旧数据 a 笔一致、b 笔差异（差异行号）】
- 没做完 / 下一步入口：【从哪个文件哪个函数接着写】
- 别再踩的坑：【一两条】
```

## 模板 C：每天只报 4 项进度

```markdown
【每天进度，只报 4 项】
不报写了多少行。只报：
1. 功能对照表打勾数：读、写、页面或接口、测试四样齐才算。
2. 已进主干的累计功能项数；排队等验收、等合并的积压各多少。
3. 测试平均耗时和排队情况（node <cheap-vibecoding 目录>/tools/test-queue.cjs stats），有没有超 10 分钟的。
4. 今天的用量（node tools/token-usage.cjs --days 1）和每步花费有没有变。
```
